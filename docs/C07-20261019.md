## 할 것(PR 하나씩, 이 순서로)

1. 방안 1, 빈 묶음 건너뛰기(수집기): 한 gentle 실행 안에서 일을 주지 않은 받기 묶음은 남은 바퀴에서 다시 묻지 않는다. 쓰기, 출처 요청, 호스트별 간격, robots, 403/429 처리, 임대·재전송은 그대로다. 실행 중에 기한이 된 다시 받기·재시도가 다음 실행으로 밀리는 것을 문서에 적는다. 운영 크기 임시 D1로 실행당 읽기 감소를 재서(C04 어림: 실행당 약 10만 행) PR에 적는다.
2. 방안 2, 실행 끝 대기열 읽기 줄이기: 실행 끝의 `/api/crawl?provider=jalan&kind=list&limit=1`이 전체 집계로 약 9만 행을 읽는다. 같은 값을 스냅숏 `status.json`에서 읽거나 하루 한 번만 집계하는 등 결과가 같은 방법을 고르고, `runReads` 예산 값도 실측으로 맞춘다.
3. 방안 3, push 배포의 스냅숏 다시 쓰기: 스냅숏을 만드는 코드와 입력이 바뀌지 않은 push 배포는 운영의 지금 스냅숏 파일을 받아 그대로 올려 D1을 읽지 않는다. 스냅숏 코드가 바뀐 배포, 수집 뒤 배포(`after_collection`), 마이그레이션이 있는 배포는 지금처럼 새로 만든다. 받은 스냅숏이 지금 형식과 맞는지 검사하고, 맞지 않으면 새로 만든다. 판정 규칙과 대조를 검사로 보인다.
