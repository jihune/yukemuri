### 3.2 두 수가 다른 이유(코드 확인)

스냅숏 `04c0aa1b509e6062`의 두 파일 값이다.

| 값 | 계산하는 곳 | 세는 것 | 자란넷 | Trip.com |
|---|---|---|---:|---:|
| `status.json` `providers[].completedDetailPages` | `lib/read-collection-status.ts` | `crawl_jobs`에서 `kind='detail'`이고 `status='done'`인 페이지 | 1,088 | 798 |
| manifest `coverage.providers.*.completed` | `lib/hotel-repository.ts` `coverageStatements` | `status='done'`인 페이지 전부(목록 페이지 포함) | 1,738 | 897 |
| 둘의 차이 | | 완료한 목록 페이지 | 650 | 99 |

- 그래서 1,738은 상세 수가 아니다. 이 값은 화면에 쓰이지 않는다(`components/`를 grep, 바닥글 문장은 상세 합계 `completedDetailPages` 1,886과 `discoveredDetailUrls` 17,036을 쓴다).
- 상세 대기는 자란넷 13,801쪽(14,889 − 1,088 − 재시도 0 − 실패 0), 목록 대기는 177쪽(13,978 − 13,801)이다. Trip.com의 실패 1쪽은 목록 페이지의 404다(roadmap C03 줄 ‘Trip 목록 404 1건’). 그래서 Trip.com 상세 대기는 1,349쪽이고 목록 대기는 0쪽이다. 이 셋은 지금 파일에서 뺄셈으로 얻은 값이다. 구현에서는 `kind`별로 직접 센다.
- 화면에 쓸 정의: 상세 페이지 완료는 `kind='detail' AND status='done'`이다. 대기는 `pending`·`running`, 재시도는 `retry`, 실패는 `failed`다. 목록 페이지는 따로 센다. 모든 상태를 합친 `completed`는 쓰지 않는다.
- ‘상세까지 모은 곳’ 1,881(`status.quality.detailRecords`, 가장 최근 관측의 `sources[0].label`에 ‘상세’)과 상세 완료 페이지 1,886은 단위가 다르다. 직접 연결한 20곳에 묶인 출처 기록은 `hotels`가 아니라 `hotel_source_observations`에 저장된다(`writeLinkedSourceObservations`). 차이 5는 이것으로 보인다(추정, 확인하지 않음).

### 3.3 한국어 이름과 설명 번역

- 한국어 이름: `names.ko`에 한글이 있으면 있다(`hotels.name GLOB '*[가-힣]*'`와 같은 규칙, `app/api/hotel-names/route.ts`). 출처는 Trip.com 한국어 페이지(`sources[].nameLocaleUrl`), 확인한 출처의 이름 패치(`hotel_name_localizations.payload`), 레포의 `data/korean-hotel-names.json`이다. 찾아봤지만 없는 곳은 `hotel_name_localizations`에 `payload`가 NULL인 행으로 남는다(`deferNameResearch`). 스냅숏 cards로 센 한국어 이름은 909곳(5.8%)이다. 자란넷 137/14,260, Trip.com 752/1,398, 직접 연결 20/20이다.
- 설명 번역: 번역이 필요한지는 `needsKoreanDescription`(한글이 없거나 외국 글자가 20자 이상이고 한글보다 많음)으로 정한다. 지금 원문의 번역은 `hotel_description_translations.source_text`가 지금 `payload.description`과 같은 행이다(`attachSourceGroups`가 상세에 붙이는 조건). 원문이 바뀐 옛 번역은 상세에 보이지 않는다. 설명은 스냅숏에 없어서 지금 비율을 계산할 수 없다. 보호된 건강 보고(`crawlHealth`)에만 `current_translation` 수가 있다.

### 4.1 두 단위

| 곳(숙소 기록) | 목록에서 1곳으로 세는 단위. 출처별 숙소 기록 하나(`hotels` 한 행, 스냅숏 한 칸)다. 같은 숙소가 자란넷과 Trip.com에 함께 있으면 2곳이다. 직접 연결한 20곳만 하나로 합친다 | 맨 위 큰 숫자, 채움 8줄, 지도 위치, 온천마을 |

### 4.2 곳 단위 8줄(분모는 모두 그 범위의 곳 수)

세 칸의 뜻은 줄마다 같다. **채움**은 값이 있다. **출처에 없음**은 출처를 확인했지만 그 정보가 없다. **아직 비어 있음**은 아직 확인하지 않았거나, 읽지 않거나, 번역하지 않았다. ‘없음’과 ‘확인 전’을 섞지 않는다(`AGENTS.md`).

| 줄 | 채움(분자) | 출처에 없음 | 아직 비어 있음 | 근거 열 |
|---|---|---|---|---|
| 상세 정보 | 가장 최근 관측이 출처 상세 페이지다 | 없음(0) | 목록 관측만 있다 | `payload.sources[0].label`에 ‘상세’(`status.quality.detailRecords`와 같은 규칙) |
| 탕 조건 | 13개 탕 항목 중 하나 이상의 값(있음 또는 없음)이 확인됐다 | 지금 규칙(v3)으로 읽은 자란넷 상세인데 탕 항목 표기가 하나도 없다 | 나머지. 목록만 있는 곳, 옛 규칙 상세, Trip.com 곳(수집기가 Trip.com 상세에서 탕 항목을 읽지 않는다) | `bath_known & BATH_FEATURE_MASK`, `sources[0].bathDataVersion` |
| 객실 정보 | 객실 수(`rooms`)나 객실 타입·사진(`roomTypes`)이 있다(D05) | v3 규칙으로 읽은 자란넷 상세인데 객실 정보가 없다 | 나머지(Trip.com은 읽은 규칙의 판 표시가 없어 없음과 확인 전을 나눌 수 없다) | `payload.rooms`, `payload.roomTypes` |
| 설립·리모델링 연도 | `facilityYears`가 있다(D04) | 자란넷 곳 전부. 자란넷 페이지에는 연도 칸이 없다(`D04-20261015.md` 조사) | Trip.com 곳 중 연도가 없는 곳(상세 전이거나 표기 없음) | `payload.facilityYears` |

| 대표 사진 | 사진 주소가 있다 | 받은 페이지에 사진이 없다 | 없음(0) | `payload.image.url` |

- 상세 정보·평점·대표 사진은 세 칸 중 두 칸만 쓴다. 다른 줄과 같은 막대 모양을 쓰려고 0인 칸을 둔다.
- 줄 순서는 값의 크기와 관계없이 고정한다. 출처 단추를 바꿔도 줄과 색이 그대로다.

### 4.3 페이지 단위

| 줄 | 분모 | 칸 |

### 4.5 온천마을별(수집 우선 20곳)

`data/collection-priorities.json`의 마을 순서다. 마을마다 곳 수, 상세 정보, 탕 조건, 한국어 이름, 건물·번지 위치 비율을 작은 막대로 보인다. 마을의 곳은 목록의 ‘온천마을’ 선택과 같은 검색(`searchSnapshot`, 마을 `query`와 도도부현)으로 고른다. 그래서 화면의 마을 수와 목록에서 그 마을을 골랐을 때의 수가 같다.

하네스 dataviz 스킬의 절차(모양 → 색 → 검사기 → 막대 규격 → 마우스·키보드 → 접근성 → 캡처 확인)를 따랐다.

| 자료 | 모양 | 고른 이유 |
|---|---|---|
| 상세까지 모은 곳 | 큰 숫자 하나(52px, Pretendard)와 굵은 막대 | 화면이 가장 먼저 답할 숫자 하나다. 큰 숫자는 화면에 하나만 둔다 |
| 출처별 상세 페이지 | 출처마다 미터(채운 부분 + 같은 색 계열의 옅은 트랙) | 출처는 둘뿐이고 각자 ‘얼마나 찼나’가 질문이다 |
| 곳 단위 8줄 | 줄마다 100% 누적 가로 막대(채움·출처에 없음·아직 비어 있음) | 전체 중 몫을 보이는 일이다. 줄 이름이 길어 가로 막대가 맞다 |
| 지도 위치 | 순서 있는 4칸 누적 막대 | 정확도는 순서가 있는 값이다 |
| 온천마을 | 마을마다 작은 막대 3개(작은 배열) | 20곳을 같은 축으로 위아래 비교한다 |

색(검사기 `validate_palette.js` 실행 결과, 흰 바탕 `#ffffff`):

- 채움 `#0a6670`(주 색 `--yk-primary`, 바탕 대비 6.67:1), 출처에 없음 `#7a8a8e`(3.59:1), 아직 비어 있음 `#d5e4e6`(1.31:1, 트랙). 한 색을 강조하고 나머지를 회색으로 두는 ‘강조’ 모양이다. 인접 칸 색맹 시뮬레이션 거리 ΔE 13.5(목표 8 이상), 정상 시각 16.5(하한 15 이상)로 통과했다. 밝기·채도 검사의 실패는 회색이라 생기는 것이고 범주 색이 아니라서 해당하지 않는다. 트랙의 대비 부족(1.31:1)은 줄마다 보이는 숫자와 ‘표로 보기’로 보완한다.
- 지도 위치 4칸 `#08434a`·`#0a6670`·`#3f8f98`·`#7aaeb4`: 순서 있는 색(`--ordinal`) 검사에서 밝기 단조, 이웃 밝기 차 0.06 이상, 가장 옅은 칸 대비 2.46:1(하한 2:1), 색상 차 2°로 모두 통과했다.
- 상태 색(실패의 빨강)은 실패 수 글자와 아이콘에만 쓰고 막대 칸 색으로 쓰지 않는다.
- 글자는 글자 색 토큰(`--yk-text`·`--yk-text-2`·`--yk-text-3`)만 쓴다. 데이터 색을 글자에 쓰지 않는다.

막대 규격: 높이 12px(큰 숫자 아래는 16px), 칸 사이 2px 흰 틈, 양 끝 4px 둥글림, 테두리 없음. 줄마다 왼쪽에 이름, 오른쪽에 채움 비율과 곳 수를 글자로 둔다. 숫자를 칸마다 붙이지 않는다. 마우스를 올리거나 키보드로 줄에 초점을 두면 세 칸의 수와 비율이 함께 보인다. 같은 값은 ‘표로 보기’ 표와 줄의 `aria-label`에도 있다. 툴팁만으로 읽는 값은 없다.

다크 모드는 U05 결정(9절 9번)대로 범위 밖이다.

## 8. 구현 계획(2단계, 답을 받은 뒤)

### 8.1 자료

- `status.json`에 `fill` 객체를 더한다. 기존 필드는 그대로 둔다. 스냅숏 형식 번호(`SNAPSHOT_FORMAT`)는 core·cards의 모양 번호라 바꾸지 않는다. 옛 화면은 새 필드를 읽지 않는다.
  - `fill.scopes.{all,jalan,trip}`: 곳 수와 8줄의 세 칸 수, 다시 번역이 필요한 수.
  - `fill.geo.{all,jalan,trip}`: 등급별 곳 수.
  - `fill.towns[]`: 마을 이름·곳 수·상세·탕 조건·한국어 이름·건물·번지 위치 수.
  - `fill.pages.{jalan,trip}.{detail,list}`: 완료·대기·재시도·실패 수, 지난 24시간 상세 확인 수.
- 계산은 `lib/search-snapshot-build.ts`의 `buildSearchSnapshot`에서 한다. 이미 모든 `hotels.payload`를 한 번 읽으므로 상세·탕·객실·연도·평점·사진·한국어 이름·설명 필요 여부는 추가 읽기가 없다.
- 추가 D1 읽기(추정, 2단계에서 잰다): `hotel_name_localizations` 전체(행 수만큼), `hotel_description_translations`의 `hotel_id`·`source_text`(행 수만큼), `crawl_jobs`를 출처·종류·상태로 묶는 질의 한 번(약 1.8만 행: 지금 상세 17,036쪽과 목록 927쪽, `skipped` 행은 세지 않음). 합쳐서 생성 한 번에 약 2만 행이다. 하루 8번 만들면 약 16만 행으로 무료 한도(하루 500만 행)의 약 3%다. `scripts/measure-search-snapshot.mjs --grow`로 생성 1회 읽기 행 수를 수정 전후로 재서 PR에 적는다.

## 10. 확인하지 못한 것

- 표본 추정 줄(객실 정보·설립·리모델링 연도·한국어 설명)은 전수가 아니다. 상세 API 표본으로 어림했다. 구현에서는 전수로 센다.
- 출처별 단추의 ‘상세 정보’는 그 출처의 상세 완료 페이지 수로 대신했다(곳 단위 출처별 수는 스냅숏에 없다). 차이는 전체에서 5다(3.2절).
- 한국어 이름의 ‘찾아봤지만 없음’은 `hotel_name_localizations`를 읽어야 해서 시안에서는 0으로 두었다.
- 탕 조건과 객실 정보의 ‘출처에 없음’(v3 자란넷 상세에 표기 없음)은 스냅숏에 판 표시가 없어 시안에서는 0으로 두었다. 표본의 자란넷 상세 73곳은 모두 탕 조건이 있었다.
- 온천마을 수는 시안에서 이름 부분일치로 어림했다. 구현은 목록의 마을 검색과 같은 함수를 쓴다.
- 실제 휴대폰과 스크린리더에서는 보지 않았다. 캡처는 headless Chromium이다.
- 수집 순서(온천마을 → 규슈·홋카이도·오키나와 → 오사카·효고 → 도쿄 인근 → 전국)별 상세 진행도 `crawl_jobs.priority`로 셀 수 있다. 화면이 길어져 이번 제안에는 넣지 않았다.
