# 유케무리 운영: 검색 목록·데이터 보존·정기 개선

2026-10-05 추가한 구조와 다음 운영 기준.

## 검색 조건과 연속 목록

검색어, 지역, 시설, 평점 출처·하한, 리뷰 하한, 료칸·즐겨찾기 모드, 정렬, 지도 보기 상태는 주소에 유지된다. 예약 날짜·인원과 숙소 상세 해시도 보존한다. 첫 화면부터 주소의 검색 조건을 서버가 적용한다. 브라우저의 즐겨찾기 비밀 식별자와 검색 세션 토큰은 주소에 넣지 않는다. `saved=1` 주소를 다른 브라우저에서 열면 그 브라우저의 즐겨찾기만 표시한다.

첫 검색에서 결과 ID와 순서를 짧게 보관한다. 다음 페이지는 이 목록으로 읽고, 카드·상세의 숙소 데이터는 현재 DB에서 읽는다. 전체 숙소 내용이나 가격을 검색 시점으로 동결하는 기능은 아니다. 수집 중 평점·이름·시설 조건이 바뀌더라도 기존 목록의 구성은 유지되며 ‘목록 새로고침’으로 현재 조건을 다시 평가한다.

- 유효 시간 20분, 보관 상한 256개 세션. 용량 상한에 도달하면 오래된 세션부터 제거하며, 해당 브라우저는 새로고침 안내를 받는다.
- 세션당 최대 50,000개 ID, ID와 집계 JSON 합계 1MB. 이를 넘으면 지역·조건을 좁히도록 안내하고 결과를 몰래 잘라내지 않는다.
- 조건·정렬·현재 즐겨찾기 ID·브라우저 범위가 일치해야 이어 읽을 수 있다. 만료 410, 범위 변경·삭제 409를 구분한다.
- 익명 일반 검색의 동일 조건은 짧은 캐시를 공유할 수 있다. 즐겨찾기 세션은 브라우저별 범위를 검증한다. 직접 새로고침은 서버의 30초 캐시도 건너뛴다.
- 다음 검색을 만들 때 만료·초과 세션을 정리한다. 검색이 없으면 만료 행이 즉시 물리 삭제되지는 않지만 API로 읽을 수 없고 전체 행 수는 제한된다.
- `stable=1`은 새 UI용 API 선택사항이다. 기존 페이지 번호 API는 호환성을 유지한다. `snapshot` 토큰으로 이어 읽을 때는 고정 순서를 사용한다.

대규모 검색 엔진 도입 없이 현재 D1에 맞는 작은 저장 목록을 사용한다. 첫 검색에서 ID를 전체 정렬하는 비용이 있으므로 데이터·트래픽이 크게 늘면 읽은 행 수와 지연을 측정하고 검색 엔진의 PIT 같은 방식을 다시 비교한다.

## 데이터 내보내기와 복원 연습

코드의 Git 이력에는 실시간 D1 수집 데이터가 포함되지 않는다. 관리 전용 `GET /api/catalog-export`는 주요 영속 테이블을 PK 순서로 응답당 최대 1,000행을 읽는다. 숙소 본문은 최대 250행, 전체 응답은 약 0.9MB로 제한하고 마지막 포함 행의 커서로 이어 읽는다. 내보내기 실행기는 독립적인 테이블을 최대 3개씩 병렬 조회하며 각 테이블 안에서는 PK 순서를 유지한다. 일반 방문자는 읽을 수 없다. 허용 테이블 밖의 조회, 임의 SQL, 잘못된 커서와 큰 limit은 거절한다. 공급자 사이트에는 요청하지 않는다.

포함: 숙소, 이름 색인, 카탈로그 메타, 수집 큐, 기존 소유자 즐겨찾기, 브라우저별 즐겨찾기, 한국어 이름 조사 결과, 원문에 연결된 설명 번역, 번역 요청, 숙소 운영 상태와 근거·변경 이력. 일시적인 요금 캐시와 검색 세션은 제외한다. 브라우저별 즐겨찾기의 식별자는 해시지만 보존본은 비공개로 취급한다.

```bash
python scripts/catalog-checkpoint.py export --out /absolute/private/checkpoint.jsonl.gz
```

터미널의 숨긴 입력 안내가 나온 뒤 현재 Site 접근 정보 JSON을 표준입력으로 전달한다. 비밀은 명령 인자·파일·자동 작업 설명에 넣지 않는다. 내보낸 파일은 0600으로 생성하고 기존 파일 덮어쓰기를 거절한다. 다른 호스트로 리디렉션되면 비밀을 전달하지 않고 중단한다.

```bash
python scripts/catalog-checkpoint.py restore --archive /absolute/private/checkpoint.jsonl.gz --out /absolute/private/recovery.sqlite
python scripts/audit-catalog.py /absolute/private/recovery.sqlite --out /absolute/private/catalog-audit.json
```

복원은 **새 로컬 DB에만** 수행한다. 파일이 이미 있으면 중단한다. 스키마·마이그레이션 해시·전체 파일 해시·테이블별 행 수·SQLite integrity_check를 검사한다. 복원한 수집 큐의 실행 중 임대와 재전송 토큰은 제거하고 running은 retry로 바꾼다. 손상된 보존본이나 일부분만 내보낸 파일은 거절한다. 운영 DB를 덮어쓰는 API는 만들지 않았다.

이 파일은 여러 HTTP 요청을 거친 **비원자적 체크포인트**이다. 시작·종료 행 수를 남기지만 일치한다고 모든 값이 같은 시점에 속한다는 뜻은 아니다. 강한 복구 보장이 필요하면 공급자 네이티브 백업·정지된 쓰기·복원 권한을 함께 확보해야 한다. [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)은 공식 문서상 유료 30일, 무료 7일의 복구 창을 제공하지만 현재 관리형 Site의 계정 플랜과 사용자가 직접 실행 가능한 복구 경로는 확인하지 않았다. 이를 현재 Site에서 직접 검증한 백업 기능으로 주장하지 않는다.

## 중복 후보 검토

`audit-catalog.py`는 읽기 전용으로 도도부현·공급자·상세·시설·한국어·관측 나이·현재 번역을 집계한다. 시설 집계는 실제 검색에 사용하는 D1 비트 색인을 기준으로 하며, 저장 원관측의 시설 값 수는 별도 항목으로 남긴다. 기존 관측의 명시적 시설 근거에서 조회 시 보강되는 값 때문에 원관측만 읽으면 확인 수를 낮게 셀 수 있다. 서로 다른 공급자의 같은 도도부현에서 정규화된 주 이름 또는 충분히 긴 주소가 일치하는 후보만 비교한다. 이름 일치와 주소 일치 또는 비근사 좌표 100m 이내가 함께 있으면 strong_review, 정확한 좌표가 1km 이상 어긋나면 conflict_review, 나머지는 review다.

확인한 특수 사례는 `data/hotel-mapping-reviews.json`에 출처와 함께 남기고 감사 결과에 별도 검토 주석으로 포함한다. 하코네 묘진다이 후보에는 공식 리뉴얼 이력과 일부 회원용 객실이 있으므로 물리적 시설과 예약 상품의 범위를 구분해야 한다.

이 등급은 동일 숙소를 확정하지 않는다. 별관·체인 지점·잘못된 주소는 직접 대조해야 한다. 원래 OTA ID·평점·즐겨찾기를 삭제하거나 후보를 자동 병합하지 않는다. 확인된 연결만 `hotel_source_groups`로 기록하여 출처 우선순위를 적용한다. 연결·해제·Google 자료 처리 기준은 [출처 우선순위](source-priorities-20261005.md)를 따른다.

## 검증

타입 검사, 조회 API 오류 처리·주소/예약 날짜 검증, 실제 파서·재시도, 기존 검색·시설·번역·즐겨찾기 격리를 검사한다. 새 Worker/D1 검사는 스크롤 중 정렬값 변경·삽입, 120개 고정 ID, 만료/다른 조건/다른 브라우저/즐겨찾기 변경 거절, 세션 용량, 주소의 첫 화면 반영, 내보내기 인증·복합 키 누락/중복 방지, 빈 SQLite 복원, 덮어쓰기·손상 거절을 다룬다. 브라우저 클릭·모바일 화면의 시각 검사는 포함하지 않는다.

온천 탐색·지역 우선순위·기존 출처 재확인과 신규/폐업/휴관 검토는 [최신 운영 계획](onsen-first-plan-20261005.md)을 따른다. 공식 운영 상태를 갱신하면 이전 연속 목록은 즉시 만료된다.

### 검색 색인·수집 우선순위 정비

공개 화면에서 신규 정비를 끝까지 기다리지 않는다. 보호된 `POST /api/crawl-prepare`가 숙소 검색 색인과 수집 우선순위를 각 500개까지 처리한다. D1 `catalog_meta`의 커서를 저장하므로 취소되거나 재시작해도 재개할 수 있다. 원본 숙소 payload는 변경하지 않는다. 검색 텍스트를 갱신할 때 동시 이름 변경을 보호하며, 진행 커서는 뒤로 이동하지 않는다. 기존 과거 초기화 단계는 유지한다.

`update-site.py --prepare-only`로 수집 전에 완료할 수 있고, 일반 수집·재확인 명령도 자동으로 먼저 정비를 완료한다. 완료 후 호출은 상태만 읽는다. 100회 제한을 넘으면 수집을 시작하지 않고 다음 실행에서 재개한다. 이 작업은 최초 데이터 준비나 정책 변경 때 필요하며 매 방문마다 전체 카탈로그를 다시 쓰지 않는다.

`external-bath-scope-v1` 정비는 리조트 공용/외부 온천이라는 명시적 Jalan 이용조건이 있는 과거 기록의 검색용 시설 열만 각 100개까지 고친다. 원본 자료는 보존한다. 수집기와 상세 응답도 같은 범위 제한을 적용하며, 별도 입장료 안내만으로 숙소 자체 온천이라고 표시하지 않는다. 독립적으로 확인한 객실탕과 공식 숙소 시설은 보존한다.
