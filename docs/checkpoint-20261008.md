## 추가한 동작

목록에서 숙소를 최대 4곳 담아 비교한다. 후보는 브라우저에 ID만 저장한다. 검색 조건·즐겨찾기와 별도로 유지한다. 후보를 빼거나 비우고, 비교에서 개별 상세를 열 수 있다.

비교표는 Trip.com 10점, Jalan 5점을 별도로 표시한다. 점수·리뷰 수·확인일·평점 출처를 함께 보여준다. Google 평점과 사진은 연결된 지도에서 확인한다. Google 운영 API 연결은 꺼진 상태를 유지한다.

온천·공용탕·전세탕·객실탕에는 출처와 확인일을 붙인다. ‘일부 객실’, ‘전 객실’, ‘객실 타입 확인’을 구분한다. 미확인은 ‘없음’으로 바꾸지 않는다. 숙소를 자동 병합하지 않는다. 검토된 연결은 기존 Jalan 시설·Trip.com 사진 우선순위를 따른다.

비교 API는 한 요청에서 1~4개 ID를 읽는다. 순서를 유지하고, 찾지 못한 ID를 따로 반환한다. 잘못된 ID·중복·5개 이상·추가 쿼리는 DB 초기화 전에 거절한다. 현재 원문에 맞는 번역만 사용한다. 새 번역·수집·Google 요청·즐겨찾기 쓰기를 실행하지 않는다. 개별 상세의 기존 번역 우선순위 동작은 유지한다.

## 수집 집계 수정

수집 현황에 상세 정보, 온천·욕탕 조건, 천연온천수, 객실 온천 확인량을 추가했다. 집계 단위는 고유 건물 수가 아닌 **출처별 숙소 기록**이다.

기존 `bath_known > 0`은 하이클래스 등급만 확인된 기록도 온천 근거로 셌다. 등급 비트를 제외하도록 공개·관리 집계를 수정했다. 조건의 ‘없음’도 확인된 사실이다. 천연온천수·객실 온천 수량은 ‘있음’으로 확인된 기록만 센다. 원관측은 바꾸지 않는다.

관리 보고서의 최근 성공 시각도 문자열 크기 대신 실제 UTC 시각으로 비교한다. 시간대 표기가 다른 기록의 순서 오류를 방지한다.

## 검사

- TypeScript 전체 검사와 Worker 빌드 통과.
- `check-comparison-worker.mjs`: 잘못된 저장값 복구, 후보 상한, 객실 범위, 미확인·없음, 요청 순서, 일부·전체 누락, 현재 번역, 휴관 상태, 개인정보 제외, 읽기 후 DB 불변.
- `check-collection-status-worker.mjs`: 등급만 확인·미확인·없음·있음 집계, 공개·관리 시간대 순서, 임대·대기·비밀 보호.
- `check-source-groups-worker.mjs`: 비교·개별 상세 일치, Jalan 시설·Trip.com 사진, 연결 갱신·해제, 원관측·즐겨찾기 보존.
- 기존 수집 큐, 출처 우선순위와 Python 실제 HTML fixture 검사 통과.

검사는 빌드한 Worker와 임시 로컬 D1에서 실행했다. 운영 수집량을 늘리거나 외부 숙소 페이지를 새로 호출하지 않았다. 화면은 가로 이동·키보드 초점·로딩·실패·재조회 처리를 구현하고 코드를 검토했다. 브라우저·모바일 시각 검사는 수행하지 않았다.
