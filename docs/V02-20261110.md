- 실행기 저장소에 PR을 열지 않는다. 실행기 PR 검사가 private 분을 쓰고 이달 계정 분이 거의 찼기 때문이다(열아홉 번째 상위 세션의 판단, 2026-11-09). P0~P1 고침만 예외이고, 열기 전에 상위 세션에 묻는다. 브랜치 `claude/v02-fable-review`에 push하는 것은 된다(`docs/`만 바꾸는 push는 `site-checks`를 부르지 않음).

- 수집 주기·상한·요청 간격·백업 시각은 바꾸지 않는다. 바꿔야 한다고 보면 근거와 함께 제안만 한다.

## 교훈

V02가 02:00:04Z 메시지에 적은 것을 옮겼다(하네스 관리 세션에 보낼 것).

1. 두 곳에 손으로 적은 판 번호를 서로 견주는 장치는 아무도 번호를 올리지 않으면 돌지 않는다. 지키려는 것(마이그레이션 목록, 표 목록)에서 값을 만들거나 그 성질을 바로 검사한다(V02-09).
2. ‘검증된 백업’이 확인한 것은 보관 파일 안의 앞뒤였고 원본을 빠짐없이 받았는지가 아니었다. 검사 이름이 말하는 것과 실제로 견주는 두 값을 나란히 적어 본다(V02-08).
3. 검사가 지키는 대상과 같은 곳(같은 저장소, 같은 무료 한도)에 있으면 함께 멈춘다. 멈춘 것을 알리는 확인은 다른 한도를 쓰는 곳에 둔다(V02-10).
4. 러너 종류를 바꾸기 전에 job의 단계별 시간을 잰다. 3분짜리 job의 95%가 한 달 넘게 바뀌지 않은 사본의 빌드였고, 나누는 쪽이 싼 러너로 옮기는 것보다 훨씬 많이 줄인다(V02-14).
5. PR에 넣는 모의는 병합 뒤에 남는 구성을 돌려야 한다. 없어질 호출을 넣은 모의는 통과해도 병합 뒤를 말해 주지 않는다(V02-06).
6. private 저장소의 매시간 cron은 20일 동안 480칸 가운데 92칸(19.2%)만 왔고, 하루 한 번 cron의 예비는 5시간 44분에서 6시간 58분 늦게 왔다. 예약을 예비로 둘 때 이 숫자로 셈한다.
7. 하위 세션이 다른 저장소의 Actions 기록이나 PR 리뷰를 읽어야 하면 세션을 열 때 그 저장소를 함께 붙인다. public 저장소라도 붙이지 않은 저장소의 API는 세션 프록시가 막고(git 읽기만 됨), 세션 안에서 push 권한으로 붙이는 것은 자동 권한 검사가 거절했다.
