## 목적과 결정

일본 온천 숙소를 시설과 출처에 따라 찾고 비교한다. 객실탕·대욕장·노천탕은 근거와 적용 범위를 표시한다. 실시간 요금 조회는 종료했다. 새로 발견한 기록과 실제 신규 개업을 구분한다. 404만으로 폐업을 판단하지 않는다.

평점은 Trip.com·Google Maps, 객실·호텔·온천은 Jalan, 대표사진은 Trip.com·Google Maps를 우선한다. 같은 숙소·같은 판매 범위가 확인된 자료만 연결한다. 원래 ID와 즐겨찾기는 보존한다. Google 운영 연결은 꺼져 있다.

정기 갱신은 LLM 대신 Python과 GitHub Actions로 처리한다. 상시 VM을 운영하지 않는다. 번역, 한국어 이름 조사, 숙소 연결과 폐업 판단은 예약에 포함하지 않는다. 이미 저장된 결과는 유지한다. 이전 에이전트 예약은 중지 상태다.

## 구현

| 영역 | 현재 구현 |
|---|---|
| 탐색 | 다국어 검색, 지역·시설·평점 필터, 지도, 상세, 주소에 검색 조건 복원 |
| 즐겨찾기 | 브라우저별 저장·검색 범위 분리 |
| 연속 목록 | 결과 ID 순서를 최대 20분 유지. 만료·조건 변경 때 새로고침 안내 |
| 출처 연결 | 검토한 공급자 ID·근거 저장. 원관측·점수 척도 보존 |
| 이름·설명 | 확인한 한국어 이름과 원문에 연결된 번역 저장. 현재 예약은 새 조사·번역 없음 |
| 운영 상태 | 공식 폐업·휴관 근거가 있으면 탐색에서 제외. 직접 상세·즐겨찾기 유지 |
| 수집 | D1 큐, 180초 임대, 재전송 보호, 공급자별 대기·백오프·만료 재확인 |
| 현황 | 출처별 마지막 성공·상세 완료·재시도·실패·대기 공개 집계 |
| 보존 | 관리 전용 분할 내보내기·빈 로컬 DB 복원. Git과 운영 DB는 별개 |

화면·API는 `app/`, `components/`, `lib/`에 있다. 스키마·마이그레이션은 `db/`, `drizzle/`에 있다. 플랫폼 빌드 도구, 검사 fixture, 자산, 잠금 파일과 과거 문서도 포함한다.

## 검증과 최근 작업

TypeScript, Worker 빌드, 기존 수집 큐와 새 현황 API 검사가 통과했다. 새 검사는 시간대 순서, 제외한 큐, 활성·만료 임대, 공급자 대기, 오류 분류, 비밀·원문 오류·즐겨찾기 보호와 읽기 후 큐 불변을 확인한다. 게시 후 실제 현황 API의 집계와 `no-store` 응답을 확인했다. 새 화면의 브라우저·모바일 시각 검사는 수행하지 않았다.

Trip.com SSR 추출을 보강했다. 연결된 출처 관측을 별도 보존해 기존 숙소의 이름·ID·즐겨찾기를 유지했다. 예약 실행의 실제 저장 결과를 확인했다. 현황 화면을 추가했다. 이번 문서 정리는 이전 README를 보존하고 짧은 현재 안내로 바꾼다.
