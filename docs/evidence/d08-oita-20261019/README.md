# D08 PR 3 근거: 오이타현 여관업 허가 목록 연결(2026-10-19)

`docs/D08-20261019.md` 16절의 PR 3 측정 근거다. L01 세션이 10-19T18:16Z–19:05Z에 쟀다.

## 받은 것

- 오이타현이 BODIK(규슈 지자체들이 함께 쓰는 공공 오픈데이터 카탈로그)에 CC BY 4.0으로 내는 `旅館業営業許可施設一覧（全件）` CSV다. 데이터셋 설명은 `令和8年3月時点`(2026년 3월 시점)이고, CSV는 2026-03-27에 올라왔다. 화면에는 설명의 월(‘2026년 3월 시점 목록’)을 보이고, 올린 날은 파일의 `uploadedAt`에만 둔다(PR #211 Codex 1회차). 오이타시 안의 숙소는 시가 따로 허가하므로 이 목록에 없다. 1,983행이다.
- `scripts/update-oita-permits.py`가 `data.bodik.jp`에 차례로 세 번 GET했다(robots.txt, 데이터셋 정보 `package_show`, CSV). 간격은 3초다. 최종본은 10-19T19:01:36Z–19:01:50Z에 받았다. 그 전에 18:16:45Z–18:16:57Z(첫 실행), 18:18:36Z–18:18:47Z(아래 운영자 이름 행 집계), 18:19:03Z–18:19:12Z(걸러내기 전 판)에도 같은 세 요청을 보냈다. robots.txt는 모든 봇에 `/user/`, `/admin/`, 검색 결과 주소 등을 막고, 받은 두 주소는 막지 않는다.
- 공개 검색 스냅숏 `044d30dd92cc6495`(생성 2026-10-19T18:20:08Z, 숙소 25,278곳)의 manifest, cards, core, text를 18:56Z–19:00Z에 공개 GET으로 받았다. 운영 키와 D1은 쓰지 않았다. 받은 파일은 저장소에 넣지 않았다.

## 커밋한 행(`data/oita-ryokan-permits.json`, 990행)

스크립트는 CSV를 메모리에서만 읽는다. 목록 ID, 시설 이름, 영업 종류, 주소, 허가번호, 허가일 여섯 칸만 쓴다. 운영자 이름(`開設者名（法人名）`)과 전화는 쓰지 않는다. CSV 원본은 저장하지 않았다. 이 저장소는 공개라서 행을 두 번 더 걸렀다.

1. 시설 이름에 개인 운영자의 이름 전체가 들어 있는 행(형태 `<성명>宅`)은 뺐다. 운영자 이름 열을 버려도 같은 이름이 시설 이름으로 남기 때문이다. 운영자 이름은 비교에만 쓰고 저장·출력하지 않았다. 처음에는 법인 운영자까지 적용해 26행이 빠졌다. 그중 16행은 시설 이름이 회사 이름과 같은 법인이라 개인정보가 아니므로, 운영자 이름에 법인 표지(`会社`, `法人`, `組合` 등)가 없을 때만 빼도록 좁혔다. 이 규칙으로 10행이 빠졌다.
2. `簡易宿所`와 `下宿` 행은 위 스냅숏의 우리 숙소와 이어진 것만 남겼다(아홉 번째 상위 세션의 18:20Z 답). 이어지지 않은 그런 행은 개인 집인 경우가 많아서, 시설 이름(성씨에 `邸`를 붙인 것 같은)과 주소만으로도 사람을 가리킬 수 있다. 이 규칙으로 983행(`簡易宿所` 977, `下宿` 6)이 빠졌다. `旅館・ホテル` 행은 이어지지 않아도 모두 남긴다.

남은 990행은 `旅館・ホテル` 898행과, 우리 숙소와 이어진 `簡易宿所` 92행이다. 어느 행이 이어졌는지는 파일의 `linked`(스냅숏 ID와 행 ID)에, 뺀 수는 `leftOut`에 적었다. 스냅숏을 만들 때 실제 연결은 저장된 숙소 기록으로 하므로, 그때 새로 이어질 `簡易宿所` 행은 다음 목록 갱신 때까지 화면에 나오지 않는다.
