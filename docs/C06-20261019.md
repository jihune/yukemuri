### 설계(10-19T12:01Z)

이어 부르기는 두 단계다.

1. 앱 `collect.yml` 끝에 `chain` job을 둔다. gentle 실행이 main에서 수집하고(쪽수가 0이 아님) 스냅숏 배포까지 성공하면, 이 job이 `gh workflow run collect-chain.yml --ref main -f after_run=<이 run id>`로 기다리는 workflow를 부른다. 이 job만 `actions: write`를 받는다. 부르기가 실패해도 수집 실행은 실패로 끝나지 않는다(`continue-on-error: true`). 그때 고리는 끊기고 실행기의 다음 예약이 다시 잇는다.
2. 새 `collect-chain.yml`의 `wait` job이 `scripts/collection-chain.mjs`를 돌린다. 앞 실행이 만들어진 때(`created_at`)에서 한 시간이 될 때까지 기다린 뒤 규칙을 보고 `collect.yml`(gentle, main)을 `GITHUB_TOKEN`의 `workflow_dispatch`로 부른다.
