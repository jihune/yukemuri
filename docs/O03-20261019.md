# O03 — 사용량 점검 자동화(Claude 없는 GitHub 예약)

기록: 2026-10-17T17:0xZ, 네 번째 상위 세션. 상태: 시작 전(10-19T12:10Z 재개 뒤 새 하위 세션이 맡는다). 이 문서는 첫 brief이고, 맡은 세션이 설계·검사·결과를 이어 적는다.

## 왜 하는가

- 사용자(10-17T16:5xZ): ‘새로 넣은 제안은 모두 권장대로 하겠고 … 특히 claude 없이 github 예약 돌리는거 좋아보임.’ (`roadmap.md` 이후 아이디어 10)
- H01 7단계에서는 Claude가 매일 `usage.yml`을 돌리고 수집 실행 로그를 읽었다. 한 번에 Claude 사용량이 꽤 든다. 7일차(10-20) 뒤에는 같은 점검을 GitHub 예약이 하고, 문제가 있을 때만 사람이 본다.

## 할 것

1. 하루 1회 점검을 GitHub 예약으로 돌린다. 공개 저장소의 cron은 60일 동안 활동이 없으면 꺼지므로, cron은 실행기 저장소(private)에 두고 앱 저장소의 workflow를 부른다(`collect.yml`과 같은 방식, `collect.yml` 첫 주석).
2. 점검 항목은 다음과 같다. 하나라도 걸리면 실패로 끝나서 GitHub 실패 메일이 간다(사용자가 실패 메일을 켜 둠).
   - 전날(UTC) 계정 전체 D1 읽기·쓰기·Worker 요청 가운데 하나라도 무료 한도의 85% 이상
   - `exceededResources`(1102·1027)가 1 이상
   - 전날 gentle 수집 가운데 0쪽 실행, 또는 26분을 넘긴 job
   - 실행기 백업 예약이 전날 실패
3. 결과 표는 run 요약(`GITHUB_STEP_SUMMARY`)에 남긴다. 사용량을 읽지 못하면(권한·네트워크) ‘0’으로 보지 않고 실패로 끝낸다(`cloudflare-usage.mjs`의 기존 규칙).
4. 기존 `usage.yml`·`cloudflare-usage.mjs`를 다시 쓰고, 새 Secret은 만들지 않는다(앱 Secret `CLOUDFLARE_API_TOKEN`에는 Account Analytics Read가 이미 있다. `usage.yml` run 38314558359).

## 지켜야 할 것

- 무료 요금제만 쓴다. 실행기 저장소 Actions 분은 월 무료 범위 안이어야 한다(지금 약 400분/월, `cloud-development.md`).
- 비밀값을 로그에 찍지 않는다. 운영 확인은 공개 GET과 이미 있는 읽기 전용 분석 조회만 한다.
- 고장 낸 입력(85% 넘김, 1102, 0쪽, 권한 없음)으로 점검이 실패하는지 대조 검사를 둔다.

## 끝나는 조건

- 실행기 예약이 앱 점검을 부르고, 정상인 날은 성공, 대조 입력에서는 실패하는 것을 Actions 실행으로 확인했다.
- `H01-20261011.md`와 `cloudflare-deploy.md`에 새 점검 방법을 적고, 상위 세션이 7일차 뒤 Claude 매일 점검을 끝낸다.
