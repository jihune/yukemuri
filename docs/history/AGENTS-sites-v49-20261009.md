# 유케무리 개발 지침

## 새 세션과 소스 기준

추가 기록: 2026-10-08T12:52:11Z / 2026-10-08 21:52:11 KST.

- 새 세션은 Sites의 현재 소스를 복구하고 `START_HERE.md`부터 읽는다. GitHub 연결을 작업 시작 조건으로 요구하지 않는다.
- Sites 소스가 화면·API·수집기의 개발 기준이다. GitHub 예약 실행은 인증된 Sites 수집기를 받도록 전환했다. 자세한 상태는 `docs/collector-runner-migration.md`와 최근 인수인계로 확인한다.
- GitHub 예약 설정·실행 이력·workflow 전환 접근이 필요하면 먼저 사용자 허가를 받는다. 이전의 GitHub 먼저 읽기 지침은 이 사용자 요청에 따라 대체한다.
- 수집기 사본 동기화를 요구하지 않는다. Sites의 승인한 수집기 소스를 검사하고 게시하면 다음 예약 실행이 그 게시 버전을 받는다. 고정 시작 도구 자체의 변경은 GitHub 작업이다.
- 배포 파일 목록을 늘리거나 시간·페이지 상한, 요청 간격을 바꿀 때는 근거와 사용자 요청을 확인한다.

## GitHub 접근 방식

추가 기록: 2026-10-08T16:33:14Z / 2026-10-09 01:33:14 KST.
사용자는 클라우드 브라우저의 GitHub 조작을 피하도록 요청했다.
작업 중단의 원인이 이 방식이라고 확정하지 않는다.

- 일반 개발은 복구한 Sites 파일과 로컬 명령으로 진행한다. GitHub 웹 편집기를 기본 개발 경로로 쓰지 않는다.
- GitHub 예약·설정·실행 이력·고정 시작 도구에 접근해야 하면 필요한 이유를 설명하고 먼저 사용자 허가를 받는다.
- 허가받은 GitHub 작업은 연결 도구·API 또는 인증된 `git`·`gh` 명령을 우선한다. 실제 접근 범위를 확인하며 인증이 있다고 가정하지 않는다.
- GitHub 도구가 404·권한 오류를 반환하면 반복 호출이나 클라우드 브라우저 조작으로 자동 전환하지 않는다. 확인한 접근 제한을 알리고 사용할 수 있는 대안을 찾는다.
- 일반 Sites 작업을 계속할 수 있으면 해당 작업을 진행한다. GitHub 접근이 꼭 필요한 부분만 미완료로 남긴다.
- 클라우드 브라우저로 GitHub를 조작하는 방식은 피한다. 다른 방식으로 처리할 수 없는 경우에만 이유를 설명하고 해당 방식에 대한 사용자 허가를 받는다.
- 사이트의 모바일·키보드·화면 검증에 필요한 브라우저 사용은 별개다.

사용자 지시와 현재 코드를 먼저 확인한다. 이 문서는 당시의 개발 기준이다.

## 제품과 자료

- 온천 숙소 탐색을 중심으로 개발한다. 실시간 요금 조회는 종료했다.
- 평점은 Trip.com·Google Maps, 객실·호텔·온천은 Jalan, 대표사진은 Trip.com·Google Maps를 우선한다.
- 출처, 점수 척도, 확인 시각과 객실 적용 범위를 보존한다. 미확인 정보를 추정하지 않는다.
- 숙소 연결은 원어명·주소·공급자 ID·판매 범위를 대조한다. 유사한 이름만으로 병합하지 않는다.
- Google API와 유료 서비스를 임의로 활성화하지 않는다.

## 변경과 검사

- 작업 전에 Git 상태와 배포 버전을 확인한다. 사용자 변경을 덮어쓰지 않는다.
- 필요한 동작을 작은 변경으로 구현한다. 의미 있는 경계 조건과 기존 동작을 검사한다.
- 수집 변경은 임대, 재전송, 대기, 출처 ID와 기존 관측 보존을 검사한다.
- 화면 변경은 로딩·실패·재시도와 좁은 화면을 확인한다.
- 데이터 갱신과 코드 배포를 구분한다. GitHub 소스와 Sites 배포를 별도로 확인한다.
- 기존 실행기 사본 대조는 예약 전환 전에 필요한 GitHub 작업에만 적용한다. 전환이 끝났다고 추정하지 않는다.

## 수집과 비밀

- 예약 수집은 Python으로 실행한다. 정기 LLM 작업을 만들지 않는다.
- 호스트별 순차 요청, robots 확인, 시간·페이지 상한과 저장된 대기를 유지한다.
- 403/429와 접근 차단을 우회하지 않는다. 404를 폐업 근거로 사용하지 않는다.
- 비밀은 환경의 Secret 또는 숨긴 표준입력으로 전달한다. 코드·인자·로그·문서·원출처에 넣지 않는다.
- 개인 즐겨찾기와 운영 DB 내보내기는 Git에 넣지 않는다.

## 글쓰기와 기록

[문장·용어 규칙](docs/writing-guide.md)을 따른다. 한국어로 짧고 구체적으로 쓴다.

- 한 문장은 한 사실이나 지시를 담는다. 주체와 동작을 분명히 쓴다.
- 조건, 수량, 적용 범위와 미확인 상태를 줄이지 않는다.
- 같은 개념에 같은 용어를 쓴다. 코드 식별자는 정확히 유지한다.
- 과장, 칭찬, 상투적 결론과 근거 없는 완료 선언을 삭제한다.
- 문서는 체크포인트로 기록한다. 시각·시간대·근거 버전·검증 범위·남은 작업을 쓴다.
- 확인한 문서만 갱신한다. 과거 기록의 날짜를 현재 날짜로 바꾸지 않는다.
- 중요한 결정·배포·중단 지점을 기록한다. 마지막에는 변경과 검사 결과를 대조한다.

ASD-STE100의 일부 원칙을 한국어에 적용한다. 영어 통제 어휘의 준수나 인증을 주장하지 않는다.

## 대기와 코드 검사 보완

기록 시각: 2026-10-08T09:17:09.588480+00:00 / 한국시간 2026-10-08 18:17:09.

- 일반 주소 이동, 로그인 화면, 자료 형식 오류와 연결 오류로 출처 전체에 긴 대기를 걸지 않는다.
- 반복된 일반 이동도 차단 근거로 쓰지 않는다. 403은 접근 거부, 429는 요청 제한으로 기록한다. 봇 차단이라고 단정하지 않는다.
- 명확한 봇 확인 화면과 출처의 Retry-After는 존중한다. robots 확인 실패 시 이번 실행의 해당 출처 요청을 중단한다. 다음 예약 실행에서 robots를 다시 확인한다.
- 기본 요청 간격과 robots 제한을 유지한다. 정상 페이지를 한꺼번에 재요청하지 않는다.
- 웹 편집기로 여러 파일을 갱신할 때 중간 커밋에 [skip ci]를 쓴다. 모든 파일과 project-files.json을 맞춘 마지막 커밋은 생략 없이 전체 검사를 실행한다.
