## 1. 사용자 승인으로 붙이는 저장소는 새 세션에 넘어가지 않는다(사용자 질문, 시험 둘)

## 2. 하위 세션이 런타임의 일반 PR 규칙을 근거로 사용자 규칙과 부딪힌다고 물었다

- 무슨 일: #275(C07) 1회차 검토의 P2 셋에 대해, C07이 ‘이 PR이 만든 P2는 다음 push에서, 다음 push가 없으면 다음 작업’(사용자 10-27 결정, 하네스 `pr-review-loop` 「Tier 2」)과 ‘자기 결함으로 확인된 지적은 지금 고쳐 push’(클라우드 세션 시스템 프롬프트의 PR 운영 규칙)가 부딪힌다며 선택을 물었다.
- 정리: 시스템 프롬프트의 규칙은 Claude Code Review 봇의 선택 지적에 대한 일반 규칙이고, 프로젝트의 사용자 결정과 하네스 스킬이 같은 경우를 더 좁게 정해 두었다. 상위 세션이 묻지 않고 사용자 규칙대로 정했고, 사용자가 같은 날 확인했다.
- 제안: `pr-review-loop` 「Tier 2」의 P2 줄 옆에 ‘런타임 기본 PR 규칙의 “자기 결함은 지금 고침”보다 이 줄이 앞선다’를 한 줄 적으면, 하위 세션이 같은 질문을 다시 하지 않는다.

## 3. 일 단위 예산과 실패선 사이에 다른 정기 소비가 빠졌다

- 무슨 일: 앱 수집은 D1 하루 읽기의 85%까지 쓰고(그 몫 안에 수집 끝 스냅숏만 예약), 매일 점검은 90%에서 실패한다. 저녁 DB 백업(약 32만 행, 한도의 6.4%)이 그 사이에 들어가지 않았다. 10-27 읽기는 89.0%였고, 수집이 83.6% 넘게 쓴 날은 백업만으로 실패선을 넘는다. 백업 시각을 정할 때의 가정(‘19:23Z 백업 뒤 수집이 백업을 본다’)은 이어 부르기 고리가 오전에 그날 몫을 다 쓰면서 깨졌다.
- 해결: 백업을 UTC 하루 시작으로 옮겨 예산 안에서 세게 했다(사용자 결정 10-28T02:3xZ, 실행기 PR #19).
- 제안(`cloudflare-free-tier`): 일 한도 예산을 정할 때 같은 날의 정기 소비(백업, 배포, 점검)를 하나씩 적고, 각각이 예산 안에서 세어지는지 밖에서 더해지는지 표시한다. 그다음 ‘예산 + 밖의 소비 합 < 실패선’을 검산한다. 예약 시각을 바꾸는 변경(이어 부르기 같은)이 오면 이 표를 다시 본다.

## 4. 하위 세션 둘의 검산이 서로 달랐다

- 무슨 일: 백업을 하루 시작으로 옮기는 비용을 C04는 ‘수집 몫이 줄지 않는다’, C07은 ‘하루 약 70쪽 준다’고 보냈다. 상위 세션이 예산식에서 다시 따져 보니, 85% 바깥에 있던 백업이 85% 안으로 들어오므로 C07이 맞았다. C04도 정정을 받아들였다.
- 제안(`counting-discipline` 또는 `child-session-orchestration`): 두 하위 세션의 숫자가 다르면 어느 쪽을 고르지 말고 식에서 직접 다시 계산한 뒤 사용자에게 올린다. 이번에는 사용자 질문을 보내기 전에 잡았다.

## 5. 룰 본문이 문장 부호만 바뀐 setup은 낱말 비교로 가려 인계를 미뤘다

- 무슨 일: setup 45(`0cd96a0`)의 `claude/CLAUDE.md`는 74줄이 바뀌었지만, 문장 부호(`**`, `—`, `;`, `:`, 괄호)를 빼고 낱말 열로 비교하니 바뀐 곳은 문장을 나눠 생긴 대문자 셋뿐이었다. 같은 비교가 setup 42의 실제 문장 변경(`dfb980c`)에서는 2곳을 찾아 대조가 됐다. 그래서 ‘룰 본문이 바뀌면 인계’ 대신 걸린 스킬 몇 줄을 기록에 옮기고 다음 날 경계에서 인계하기로 했다.
- 제안(`cloud-session-ops` §8 「When to hand off」): ‘A change to the rule body is not copied; hand off’에 ‘문장 부호만 바뀐 판인지는 부호를 뺀 낱말 비교와 그 대조로 가린다’를 더하거나, 하네스 알림이 ‘룰 본문 뜻 바뀜 없음’을 명시해 주면 받는 세션이 같은 비교를 되풀이하지 않는다.

## 6. 작은 시행착오

- 기록에 사용자 지시 시각을 쓸 때 마지막으로 본 시각(04:5xZ)을 적었다가, 같은 명령의 `date -u` 출력(13:29Z)을 보고 바로 고쳤다. 사용자 메시지가 몇 시간 뒤에 올 때가 있으니 지시 줄을 쓰기 전에 `date -u`를 먼저 본다(전역 룰 5절과 같음, 새 규칙은 필요 없음).
- 하네스 저장소를 읽으려고 붙인 뒤 `register_repo_root`를 부르지 않았는데도, 세션이 다시 열리며 그 저장소의 `CLAUDE.md`·`AGENTS.md`(하네스 저장소 작업 규칙)가 이 세션의 프로젝트 지침으로 실렸다. 읽기만 할 저장소를 붙이면 그 저장소의 작업 규칙이 다른 프로젝트 세션에 섞일 수 있다. 하네스 관리 세션이 알고 있으면 충분하다.
