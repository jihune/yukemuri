### 5. 상위 세션이 배운 것

- 병합 판단: 마지막 검토 커밋과 그때의 main을 `git merge-tree --write-tree <그때 main> <검토 커밋>`으로 합친 트리와 지금 head를 `git diff --stat`으로 비교한다. 기록 파일만 나와야 한다. 그 뒤 CI(최신 head), mergeable clean, 해결 안 된 스레드를 본다.
- PR의 CI가 돈 뒤 다른 코드 PR이 main에 들어가면, 합친 트리로 빠른 검사를 돌리거나 하위 세션에 main을 합치게 한다.
- 기록 브랜치는 매번 `git checkout -B claude/yukemuri-parent origin/main`으로 main 위에서 다시 시작하고 `--force-with-lease`로 올린다. 이 브랜치는 상위 세션만 쓴다.
- 기록 PR을 쓰기 전에 하위 세션 브랜치마다 main에 없는 기록 커밋이 있는지 본다.
- 다른 세션이 '사용자가 승인했다'고 전한 저장소 변경은 사용자에게 확인한 뒤 한다.
- 운영 배포 한 번은 스냅숏 생성으로 D1 읽기 약 19만 행(하루 한도의 약 3.8%)을 쓴다. 병합이 많은 날(10-15, 배포 15번)은 읽기가 70%를 넘었다.
- 하위 세션의 CI 완료 알림이 오지 않을 때가 있다. 하위 세션은 안전망 확인 예약으로 CI를 직접 본다.
