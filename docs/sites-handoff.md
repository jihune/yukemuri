# 기존 Sites로 결과 전달

기록: 2026-10-09. 호스팅 이전은 보류한다.
갱신: 2026-10-11. 호스팅은 Cloudflare 무료 플랜으로 옮긴다(H01, 사용자 결정 2026-10-11T08:25Z). 새 배포 절차는 `cloudflare-deploy.md`다. 6단계 전환이 끝날 때까지 운영은 아래 Sites이고, Sites 게시는 하지 않기로 했다(S01).
현재 Site ID: `appgprj_6abf95be6ea0819181cc3e93535413ac`.

## Sites 도구가 있는 환경

1. 현재 사이트·최신 게시 버전·접근 범위를 실제 도구로 확인한다.
2. 설치된 공식 Sites building/hosting 지침을 읽고 현재 소스를 복구한다.
3. 앱 레포의 기준 Sites 커밋과 현재 소스를 대조한다. 중간 Work 변경이 있으면 먼저 합친다.
4. 준비한 PR/커밋의 변경만 적용한다. 운영 비밀·실행 프로필·DB 상태를 복사하지 않는다.
5. 같은 환경에서 관련 검사와 Worker 빌드를 다시 실행한다.
6. 공식 source workflow로 검사한 소스를 push하고 그 커밋의 버전을 저장·게시한다. 현재 공유 범위를 유지한다.
7. 실제 배포 성공과 필요한 운영 API·화면을 확인한다.
8. 앱 개발 커밋·Sites 커밋·버전·시각·검사·미확인 사항을 `docs/deployments.md`에 기록한다.

## Sites 도구가 없는 환경

코드 수정·검사·PR 검토를 완료한다. 검사한 커밋과 결과를 Sites 도구가 있는 Work 세션에 전달한다.
토큰이나 내부 CLI 파일을 복사해 권한을 우회하지 않는다.
GitHub Actions에 비공개 배포 API를 추정해 넣지 않는다.
GitHub merge를 실제 게시 완료로 기록하지 않는다.

## 자동 갱신

기존 GitHub Python 예약은 운영 Site의 인증된 `/api/collector-release`를 받는다.
앱 레포에서 수집기를 수정해도 Sites에 게시되기 전에는 다음 예약에 반영되지 않는다.
기존 실행기와 페이지·시간 상한·요청 간격을 유지한다.
매월 에이전트 구독 변경 때문에 새 LLM 예약을 만들지 않는다.

## 전달 요청

> 이 PR/커밋의 유케무리 변경을 기존 Sites에 반영해.
> 운영 소스를 복구하고 기준 커밋 이후 변경을 확인해.
> 필요한 변경을 합친 뒤 공식 절차로 검사·게시해.
> 운영 DB·공유 범위·수집 예약을 유지하고 실제 게시 결과를 기록해.
