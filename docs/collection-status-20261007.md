# 출처별 수집 현황

기록 시각: 2026-10-07T08:26:00Z / 한국시간 17:26. 사이트 v34의 체크포인트다.

기존 전국 수집 현황을 펼치면 자란넷·Trip.com의 최근 성공 시각, 상세 완료 페이지 수, 재시도·실패 수, 활성 임대 및 출처 대기 상태를 확인한다. 현황 새로고침은 운영 DB의 기록만 읽으며 원출처 수집이나 Google API 요청을 시작하지 않는다. 평점·객실·온천·사진의 출처 우선순위는 그대로 유지한다.

`GET /api/collection-status`는 공개 집계만 반환한다. 전체 유지보수 보고서 `/api/crawl?report=1`은 계속 접근 키가 필요하다. 공개 응답에는 큐 URL, 임대 토큰, 원문 오류, 비밀, 즐겨찾기, Google 자료가 없다. 오류는 한정된 분류와 건수로만 표시한다. 비일본 숙소로 제외된 큐는 성공·실패 집계에서 제외한다.

시간 비교는 `unixepoch(fetched_at)`으로 수행하므로 같은 날짜의 서로 다른 UTC 오프셋을 문자열 순으로 비교하지 않는다. 활성 임대는 현재 시각 이후인 것만 포함한다. 일반 3초 요청 간격은 출처 중단으로 표시하지 않으며, 30초가 넘게 남은 저장된 공급자 대기는 재개 가능 시각을 표시한다. 시각은 한국시간으로 표시한다. 마지막 성공은 해당 출처의 최근 페이지 확인이며 전체 숙소의 확인일을 뜻하지 않는다. 집계 읽기는 단일 시점의 원자적 스냅샷이 아니다.

Google 상태는 서버의 명시적 사용 설정과 키 존재 여부만 확인한다. 실제 API 인증 성공을 주장하지 않는다. 사용 설정이 있을 때에도 숙소 상세에서 요청할 때만 기존 Google 경로를 사용한다. 현재 운영 연결은 미설정 상태다.

## 검증

- TypeScript 검사 및 Worker 빌드 통과.
- `scripts/check-collection-status-worker.mjs`: 공개 집계, 시간대 순서, 제외된 자료, 활성/만료 임대, 요청 간격과 공급자 대기 구분, 오류 분류, 비밀/원문 오류/큐 식별자 보호, 읽기 후 큐 불변, 전체 보고서 접근 보호, 기존 페이지 응답 확인.
- 기존 `scripts/check-crawl-queue-worker.mjs` 통과: 동시 선점·재시도·임대 복구·공급자 대기·상세 ID·오래된 자료 및 이름 별칭 거부·조회 인덱스 유지.
- 실제 GitHub `schedule` 실행 #2(2026-10-07 05:46 KST)와 #3(10:03 KST)의 성공 확인. #3은 16페이지 처리, 86개 관측 저장, `jalan-324866` 재조회 및 정상 종료를 기록했다. 운영 DB 읽기에서도 숙소 기록 11,695개를 확인했다. 정확한 3시간 실행 시각을 보장하지 않는다.

별도 테이블, 스키마 변경, 원출처 추가 요청, 새 에이전트 예약, 유료 API 활성화는 추가하지 않는다.
