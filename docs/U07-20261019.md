## PR 가 — 필터 글자 밀림·옵션 도움말·이름 복사·이름 순서

기록: 2026-10-18T01:5xZ. 설계와 고친 파일이다. 검사 결과는 아래 5에 적는다.

### 1. 필터 체크 표시 때 글자가 밀려 잘림(할 것 1)

운영 화면(2026-10-18T01:1xZ, 공개 GET)에서 쟀다. 1280px 패널의 탕 조건 버튼은 폭 100px이다. 누르면 이름 앞에 ‘✓ ’가 붙어 이름 글자가 오른쪽으로 17px 밀린다(`.filter-chip[aria-pressed=true]>span::before`). 그래서 ‘천연온천 65’, ‘카케나가시 5’, ‘니고리유 10’처럼 숫자가 잘렸다. 누르기 전에도 ‘카케나가시 577’은 3px 넘쳤다. 이름과 숫자와 체크 표시가 한 줄에 들어갈 폭이 없었다.

고친 방법: 체크 표시 자리(14px)를 처음부터 이름 앞에 둔다. 누르기 전에는 빈 네모, 누르면 ✓다. 탕 조건 버튼은 숫자를 이름 아래 줄에 둔다. 그래서 누르기 전후에 이름 글자 위치·줄 수·숫자 줄·버튼 크기가 같고, 숫자가 다섯 자리(전국 23,032곳이 최대)여도 잘리지 않는다. ‘내 기준’은 넓은 버튼이라 한 줄 그대로다. 상태는 색과 함께 빈 네모·✓ 모양으로도 구분된다.

### 2. 옵션별 도움말(할 것 2)

옵션 15개(빠른 조건 7개, 묶음 안 스위치 8개)마다 한두 문장 도움말을 둔다. 문구는 수집 규칙(`scripts/crawler/collect.py`, `lib/hotel-bath-facts.ts`)과 `lib/collection-status.ts`의 말(자란넷, 확인된, 객실 타입)로 썼다. 평점 선택 상자 세 개는 묶음의 ‘?’ 설명이 그대로 맡는다.

### 1. 쓰는 기능과 근거

- 브라우저에 들어 있는 Translator API(`Translator.availability()`·`create()`·`translate()`)를 쓴다. 번역은 방문자의 기기 안에서 돌고, 결제·API 키·외부 번역 서버 요청이 없다.
- 공식 문서(2026-10-18 curl로 원문을 받아 직접 읽음):
  - https://developer.chrome.com/docs/ai/translator-api (머리 표기 ‘Last updated May 20, 2025’): “The Language Detector and Translator APIs work in Chrome on desktop. These APIs don't work on mobile devices.”
  - https://developer.chrome.com/docs/ai/get-started: “The Translator and Language Detector APIs use expert models. All other APIs use a language model”. 이 번역은 언어 모델(LLM)이 아니라 번역 전용 모델이다.
  - https://developer.chrome.com/docs/ai/built-in-apis: “The Translator API is available from Chrome 138 stable.” 같은 페이지의 지원 표는 Chrome 138, Edge 148이고 나머지는 지원하지 않는다.
- 지원 범위: 데스크톱 Chrome 138 이상과 Edge 148 이상이다. 휴대폰(Android·iOS), Safari, Firefox는 쓸 수 없다.
- 처음 쓸 때 번역 모델을 받는다. 일본어→한국어는 영어를 거쳐 언어 팩 두 개(en-ja·en-ko)를 받는다. 구글 컴포넌트 서버 응답으로는 합쳐 약 113MB다(공식 문서에는 크기가 없음, 조사 서브에이전트가 10-18에 조회). 모델 받기는 사람이 단추를 누른 직후에만 시작할 수 있어 단추를 누를 때 `create()`를 부른다.
