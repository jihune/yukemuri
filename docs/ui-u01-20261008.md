## 재현과 수정

React와 실제 Radix Sheet를 JSDOM에 렌더링했다.
운영 API와 지도·사진·일부 표시 컴포넌트는 검사 자료로 대체했다.
실제 브라우저의 렌더링이나 입력 검사와 구분한다.

| 항목 | 수정 전 확인 | 수정 |
|---|---|---|
| 비교 → 상세 → 닫기 | 비교가 닫히고 목록으로 돌아감 | 비교를 상세 아래에 유지. 상세 닫기와 뒤로 가기로 비교 복귀 |
| 비교 후보 제거 | 제거된 버튼에서 포커스가 끊김 | 다음 후보의 제거 버튼으로 이동. 마지막 후보는 닫기 버튼으로 이동 |
| 모두 비우기 | 사라진 비우기 버튼에서 포커스가 끊김 | 먼저 닫기 버튼으로 이동한 뒤 비움 |
| 수집 현황 0건 | 0이라는 숫자 외에 빈 상태 안내가 없음 | 저장된 기록이 없다는 안내 추가 |
| 수집 현황 표 | 표의 가로 스크롤 영역에 명시적 포커스 대상이 없음 | 이름 있는 포커스 영역과 방향키 처리 추가 |

비교와 수집 현황의 표에 좌우 이동 안내를 추가했다.
방향키 처리는 표 영역 자체에 포커스가 있을 때만 실행한다.
셀의 링크·버튼·근거 보기에 전달된 키는 가로 이동에 사용하지 않는다.
비교표의 기존 브라우저 기본 방향키 동작은 실제 브라우저에서 확인하지 못했다.
JSDOM은 그 기본 동작을 구현하지 않는다.
수정 전 방향키 검사 실패만으로 기존 브라우저 동작이 고장 났다고 단정하지 않는다.

후보 제거 시 남은 자료와 버튼을 유지하며 새 정보를 조회한다.
새로 추가된 미조회 후보에는 이전 자료를 사용하지 않는다.
새로고침 중에도 버튼을 유지해 포커스를 보존한다.
`aria-disabled`와 클릭 조건으로 중복 요청을 막는다.
수집 현황 조회 상태는 `aria-live`로 알린다.
좁은 화면의 수집 현황 표·도구 글자는 14px로 맞췄다.
닫기 버튼이 줄어들지 않게 했다.

## 미확인 범위

관리되는 검사용 미리보기는 실행 상태를 반환했다.
허용된 검사 주소에서 브라우저의 `Page.navigate`가 시간 초과를 반환했다.
같은 탭 확인의 `Page.getFrameTree`도 시간 초과를 반환했다.
다른 주소·포트·운영 URL로 브라우저 검사를 대체하지 않았다.
이 제한을 사이트 결함이나 GitHub 문제라고 단정하지 않는다.

360px·390px 실제 렌더링은 확인하지 못했다.
실제 터치 가로 스크롤·화면 넘침·표의 고정 열·닫기 버튼의 가림은 확인하지 못했다.
전체 Tab 순서·Enter와 Space의 실제 버튼 활성화·바깥 영역 닫기도 미확인이다.
스크린리더의 읽기 순서와 모바일 브라우저의 주소창·안전 영역도 미확인이다.
JSDOM의 `matchMedia`는 모바일 조건만 모사한다.
화면 너비나 CSS 레이아웃은 검증하지 않는다.
따라서 U01 전체 완료로 표시하지 않는다.
