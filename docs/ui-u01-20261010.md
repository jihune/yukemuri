# U01 실제 브라우저 검사와 비교 막대 가림 수정

기록: 2026-10-10T11:50Z / 2026-10-10 20:50 KST.
작업 환경: Claude Code 웹 클라우드(Ubuntu 24.04.5). 작업 브랜치: `claude/pensive-bell-odhgp8`.
시작 기준: main `ba8a381f6d6748f9c472b9d937c1090d5d48368a`.
Sites에는 게시하지 않았다. 이 환경에 Sites 도구가 없다.

## 검사 환경

- Node 24.21.0(nvm 설치), pnpm 11.25.0, Python 3.13.16을 사용했다.
- Chromium 141.0.7390.37 headless와 Playwright 1.56.1을 사용했다. Playwright는 무시되는 `.sites-runtime/u01-browser`에 설치했다. 제품 의존성과 잠금 파일은 바꾸지 않았다.
- 화면은 360×780과 390×780이다. 모바일·터치 모드와 기기 배율 2를 사용했다.
- 개발 서버는 portable 모드의 `node scripts/run-framework.mjs dev`다. 로컬 D1(`.wrangler/state`)에 `drizzle/` 마이그레이션 13개를 적용했다. 첫 요청에서 체크인된 스냅샷의 기록 1,655개를 불러왔다. 이 수치는 운영 D1 수치가 아니다.
- 검사는 외부 요청(사진·지도 타일)을 차단한다. 이 컨테이너의 프록시도 해당 요청을 거절했다.

## 발견과 수정

| 항목 | 확인 | 수정 |
|---|---|---|
| 비교 막대와 하단 링크 | 비교 후보가 있으면 목록 끝에서 하단 ‘사진 출처’ 링크가 고정된 비교 막대에 가려졌다. 360·390px에서 링크는 669px, 막대는 646~692px에 있었다. 더 내릴 수 없어서 링크를 누를 수 없었다. 1280px에서도 가려졌다. | 비교 막대가 있을 때만 푸터 아래 여백을 늘렸다. 900px 이하는 150px, 그보다 넓으면 86px이다. 막대 위치·높이 46px·간격 16px으로 계산했다. |

수정 범위는 `app/globals.css`의 규칙 두 개다. 비교 막대가 없을 때의 여백은 그대로다.
대조: 같은 서버에서 수정 전 여백 95px을 주입하면 두 폭 모두 링크가 가려졌다. 수정본에서는 링크가 614px로 올라가 가려지지 않았다. 1280px에서도 링크가 가려지지 않았다.

## 검사 결과

`node scripts/check-u01-browser.mjs`가 폭마다 32개, 모두 64개를 통과했다. 같은 결과를 두 번 확인했다. [근거](evidence/ui-u01-browser-20261010.json).

- 목록: 가로 넘침이 없다. 터치 2회·Space·Enter로 4곳을 담는다. 다섯 번째 후보는 안내 후 거절한다. 비교 막대와 ‘지도 보기’ 버튼이 겹치지 않는다. 목록 끝의 버튼·링크가 가려지지 않는다.
- 비교 시트: 화면 안에 있고 가로 넘침이 없다. 열면 닫기 버튼에 포커스가 간다. 닫기·도구 버튼이 가려지지 않는다. Tab 포커스가 시트 안에서 순환한다. 닫기 버튼에서 Shift+Tab을 누르면 마지막 요소로 간다.
- 비교표: 방향키와 터치로 가로 이동한다. 첫 열은 고정된다. ‘다시 확인’은 Enter와 Space로 실행된다.
- 비교 → 상세 → 닫기 버튼·Escape·뒤로 가기: 비교로 돌아오고 숙소명 버튼에 포커스가 돌아온다. 상세 닫기 버튼은 가려지지 않는다.
- 후보 제거 후 다음 제거 버튼에 포커스가 간다. 모두 비우기 후 닫기 버튼에 포커스가 가고 빈 안내가 보인다. Escape로 닫으면 비교 열기 버튼에 포커스가 돌아온다. 마지막 후보를 제거하면 닫기 버튼에 포커스가 간다.
- 수집 현황: 로딩 안내가 보인다. 연 화면에 가로 넘침이 없다. 표는 방향키와 터치로 가로 이동한다. 새로고침 버튼 높이는 44px 이상이다. 새로고침 실패 시 오류 안내와 마지막 결과가 남는다. Space 재시도 성공 후 오류 안내가 사라지고 포커스가 유지된다. Enter로 열 수 있고 첫 조회 실패 안내가 보인다. 빈 기록 안내가 보인다. Space로 닫을 수 있다.
- 바깥 영역 닫기: 360·390px에서는 시트가 화면 전체 너비라 바깥 영역이 없다. 해당 없음으로 기록한다.

## 검사 중 확인한 사항

- 상세를 닫으면 포커스는 닫힘 애니메이션이 끝난 다음 프레임에 숙소명 버튼으로 돌아온다. 그 전 약 0.3~0.6초 동안 포커스는 body에 있다. 360px에서 Escape 닫기를 24회 반복했고 모두 0.54초 안에 돌아왔다. 결함으로 판단하지 않았다.
- `Input.synthesizeScrollGesture`는 이 headless Chromium에서 스크롤하지 않았다. 일반 div 대조에서도 0px이었다. 검사는 `Input.dispatchTouchEvent`의 터치 이동을 사용한다. 같은 대조 div가 170px 이동했다.
- 기본 목록은 끝 근처에서 40곳씩 더 불러온다. 목록 끝 검사는 ‘노보리베츠’ 검색 결과 4곳을 사용한다.
- `html`에 smooth scroll이 있어서 검사는 즉시 스크롤한 뒤 끝에 도달했는지 확인한다.

## 미확인 범위

- 실제 모바일 기기, 모바일 브라우저 주소창과 안전 영역은 확인하지 않았다.
- iOS Safari의 탭 포커스 동작과 그에 따른 포커스 복귀는 확인하지 않았다.
- 스크린리더 읽기 순서는 확인하지 않았다.
- 외부 사진과 지도 타일 표시는 확인하지 않았다.
- 운영 D1 자료로 렌더링한 표 너비는 확인하지 않았다.

## 범위 밖 관찰

1280px에서 4곳 검색 결과의 끝까지 내렸을 때 두 가지를 확인했다. 비교 막대와 관계없고 이번 수정 전부터 있었다.

- 왼쪽 고정 필터 패널의 아래쪽 체크박스가 푸터에 가려진다.
- 숙소를 선택하면 지도 미리보기 카드가 Leaflet 저작권 링크를 가린다.

U01 범위가 아니므로 수정하지 않았다. 넓은 화면·지도 작업(U02 등)에서 다시 확인한다.

## 재실행

개발 DB 준비는 `cloud-development.md`의 ‘개발 DB와 화면 검사’를 따른다. 개발 서버를 띄운 다른 터미널에서 실행한다.

```sh
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install --prefix .sites-runtime/u01-browser --no-save --package-lock=false playwright@1.56.1
node scripts/check-u01-browser.mjs http://127.0.0.1:5173 docs/evidence/ui-u01-browser-<날짜>.json
```

Claude Code 클라우드에는 Playwright 1.56.1용 Chromium이 `/opt/pw-browsers`에 있다. 다른 환경에서는 `npx --prefix .sites-runtime/u01-browser playwright install chromium`이 필요할 수 있다.
마지막 줄의 `checks=… failed=… PASS|FAIL`로 판정한다. 실패가 있으면 종료 코드가 1이다.
